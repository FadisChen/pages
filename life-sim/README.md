# 八十年｜人生模擬器

> 設計討論稿 v0.5｜工作名稱：八十年（Eighty Years）

## 一句話

用像素風格逐月走過一個人的人生；每個選擇和意外都可能開啟不同人生故事，旅程可能走到 80 歲，也可能提早結束，最後依實際經歷生成回顧。

## 已確認的設計方向

- **行事曆預設**：MVP 先採當代台灣行事曆，涵蓋學期、寒暑假與常見工作節奏；資料結構保留地區設定，之後可擴充其他地區。
- **事件密度**：採混合節奏。每月都能推進，但平常月份只給簡短生活摘要並可快轉；較少數的重要事件才暫停遊戲，讓玩家做選擇。
- **人生分歧**：玩家選擇會影響職涯、健康、財務、興趣、家庭與關係等多個面向，逐步形成不同的人生故事。友情是其中一部分，不是唯一主線。
- **敘事參考**：日劇《重啟人生》（ブラッシュアップライフ）。參考生活喜劇的日常觀察、自然閒聊與平凡生活裡的幽默；用來呈現選擇如何逐漸改變人生。
- **提前結束**：少數重大突發事件可能讓人生在 80 歲之前結束；結束後立即生成該段人生的回顧。
- **事件機率**：事件種類與出現機率參考人生階段、月份／季節、生活狀態、過往選擇與隨機性；避免每月固定發生同一種事件。

## 敘事基調草案

- 生活細節放在前景：課堂、通勤、工作、家庭、興趣等普通時刻，讓人生轉折自然發生在日常之中。
- 幽默來自觀察、反應與對話節奏，不要求每個事件都安排笑點。
- 讓選擇累積成不同機會、限制與後續事件；玩家不只是在選當下結果，也在慢慢走向一種人生。
- 家庭、友情、伴侶、職涯、健康、金錢與個人興趣都能成為故事線，沒有單一必須追求的「成功人生」。
- 大多數月份輕鬆平實，少數月份帶來苦甜轉折；重大意外可能打亂原有方向，早逝結局以克制方式呈現，重點放在人生經歷與留下的影響。

**事件示例｜升學選擇**

高三成果展結束後，老師提醒大家這週要交升學志願。家人傳來一份整理好的科系清單；你自己的作品集還有兩頁沒完成，週末打工的店長也問你能不能多排一班。

- 依家人建議填志願，先走穩定、熟悉的方向。
- 把週末留給作品集，申請一直想讀的設計科系。
- 先多接幾班工作，存一筆錢再決定下一步。

不同選擇會改變後續的學習、工作機會與生活壓力，未來也會遇到不同的人生事件。

## 核心遊戲循環

1. **建立角色**：設定姓名、出生年月、生活地區／行事曆、起點環境、個性傾向，以及此生最看重的事。
2. **逐月推進**：模擬人生，每次推進一個月。平靜月份顯示簡短生活摘要；玩家可逐月前進，也可快轉到下個事件。
3. **機率性事件**：依人生階段、季節、學校或工作狀態、個人狀態和過往經歷調整事件種類與機率。
4. **做出選擇**：重要事件提供 2–3 個行動，也可輸入自訂行動。部分選擇會留下多年後才觸發的影響。
5. **人生結束與回顧**：到 80 歲或遭遇提早終結人生的事件後，整理重要時刻、人生狀態變化、關係故事、成就與遺憾，生成符合實際經歷的回顧。

## 人生階段與事件池

階段與年齡範圍先採可調整設定。MVP 的事件日曆以當代台灣為預設；地區與行事曆資料分離，避免未來新增地區時重寫遊戲規則。

| 階段 | 事件例子 |
| --- | --- |
| 幼年 | 家庭變化、興趣萌芽、搬家、健康與照顧 |
| 求學 | 開學、考試、社團、升學選擇、寒暑假活動 |
| 青年／初入職場 | 求學或求職、離家、實習、初次工作與獨立生活 |
| 職涯／家庭生活 | 專案、年度考核、升遷、轉職、家庭安排與休假 |
| 中年 | 職涯轉折、照顧責任、財務決定、健康與興趣 |
| 晚年 | 退休安排、健康變化、家庭相聚、回望往事與生活重心轉換 |
| 各階段 | 低機率突發事件；部分事件可能造成長期影響，極少數可能提早結束人生 |

事件權重會參考角色身份、目前狀態與事件冷卻時間，避免連續幾個月都遇到同類事件。固定時節事件（如考試、假期、年度考核）由台灣行事曆設定提供；突發事件則依當下情境與過往選擇調整機率。涉及生命終點的事件出現機率應低，且由遊戲引擎管理觸發條件，維持可重現的存檔狀態。

## 人生狀態與事件規則草案

- **多面向狀態**：健康、情緒、經濟、工作／志業、關係與興趣，各以少量數值搭配文字描述。
- **多條人生線**：家庭、友情、伴侶、職涯、健康、金錢與興趣都可發展，不要求每次遊玩都走同一條主線。
- **事件與機率**：遊戲引擎依階段、月份、身份和狀態決定是否觸發事件；Gemini 撰寫事件內容及選項，不直接決定抽中機率。
- **意外後果**：一般事件影響狀態與後續機會；罕見的重大事件可以直接終止人生。若提早結束，遊戲立即保存結局並進入人生回顧。
- **延遲後果**：選擇先記錄成事件與狀態變化，後續事件可以引用它；避免 Gemini 任意改寫整份存檔。
- **人生回顧**：依角色起點、玩家重視的事與實際經歷整理「這一生如何成形」，並標示生命長度和主要轉折，不以單一分數排名。

## 存檔與重來草案

- **自動存檔**：每次月份推進或事件結束後保存，包含年月、人生階段、行事曆設定、狀態、重要關係、未來待觸發的後果、事件紀錄與隨機種子。
- **保存結局**：人生提早結束或到達 80 歲時保存最終狀態與回顧，避免意外後遺失完整故事。
- **繼續人生**：重新開啟遊戲時，可從最近一次自動存檔繼續。
- **重新開始**：開啟新人生時不覆蓋舊人生；完成或放棄的存檔可收進「人生相簿」。
- **重玩同一起點**：保留角色初始設定，可選擇沿用相同隨機種子重現事件序列，或使用新種子體驗不同人生。
- **資料位置**：MVP 先存在本機瀏覽器，提供多個存檔位；API key 與人生存檔分開處理，不納入匯出資料。

## Gemini BYOK 草案

- 由玩家在設定頁輸入自己的 Gemini API key；請求從瀏覽器直接送往 Google API，不經遊戲伺服器。
- 指定模型 ID：`gemini-3.5-flash-lite`。
- Gemini 負責事件敘述、選項文字與回顧草稿；遊戲引擎負責事件抽選、驗證回應、套用數值規則、處理提早終結與保存年表。
- 以結構化 JSON 回應降低格式錯誤；API key 不進存檔匯出，也不寫入原始碼或 Git。
- 金鑰儲存方式待討論：每次工作階段輸入，或由玩家選擇儲存在本機瀏覽器。

官方模型文件列出此模型支援結構化輸出，並指出 Gemini 3.5 Flash-Lite 不應傳入已棄用的 `temperature`、`top_p`、`top_k` 等參數。實作前仍會依官方 API 文件確認請求格式與可用能力。

## 像素美術方向

- 溫暖、帶懷舊感的低解析度像素畫；畫面像一本會隨年歲改變的生活手帳。
- 角色立繪隨年齡成長，背景、季節與生活物件記錄人生階段。
- 主畫面可由「人物場景 + 年齡／狀態面板 + 月份時間軸 + 事件對話框」組成。
- 季節背景和小物件依月份切換，呈現人生故事隨時間變化。

## MVP 範圍建議

先完成一條可玩完的 80 年人生：角色建立、逐月推進、依人生階段抽選事件、選擇與延遲後果、多條人生線追蹤、自動存檔、繼續／重開、可能的提前終結，以及結尾回顧。採混合事件密度、台灣行事曆預設與生活喜劇敘事。暫不加入多人、雲端帳號或需要伺服器保存的資料。
