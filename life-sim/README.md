# 八十年｜人生模擬器

> 設計討論稿 v0.1｜工作名稱：八十年（Eighty Years）

## 一句話

用像素風格走過一個人的 80 年人生；玩家的選擇、關係與突發事件交織成一段獨一無二的生命故事，最後生成一份人生回顧。

## 核心體驗

重點不是把人生玩成高分競賽，而是看見選擇如何累積：一次搬家、一段關係、一份工作或一場意外，可能在多年後才顯出影響。結局回顧呈現玩家如何生活，不替人生判定單一的成功標準。

## 初步遊戲循環

1. **建立角色**：設定姓名、起點環境、個性傾向，以及此生最看重的事。
2. **推進年份**：遊戲跨越 0–80 歲。日常年份可以快速略過，遇到重要抉擇或突發事件時停下來。
3. **做出選擇**：每個事件提供 2–3 個行動，也可輸入自訂行動。
4. **記錄後果**：遊戲引擎更新狀態與關係，留下重要事件；部分選擇可形成延遲影響。
5. **人生回顧**：到 80 歲後生成重要時刻年表、人生狀態變化、關係故事、成就與遺憾，以及一段貼合玩家經歷的回顧。

這個節奏是初步假設：遊戲涵蓋完整 80 年，但每年不一定都需要一次 Gemini 對話。

## 遊戲系統草案

- **可理解的狀態**：健康、情緒、經濟、工作／志業、關係，各以少量數值搭配文字描述。
- **重要人物**：家人、朋友、伴侶、同事等角色有自己的關係狀態與共同記憶。
- **突發事件**：由個人狀態、既有關係與隨機事件共同觸發，讓事件與這段人生相關，而不是每局都抽到同一批題目。
- **延遲後果**：選擇先記錄成事件與狀態變化，後續事件可以引用它；避免 Gemini 直接任意改寫整份存檔。
- **人生回顧**：不以財富或職涯單一排名，依角色起點、玩家重視的事與實際經歷，整理「這一生如何成形」。

## Gemini BYOK 草案

- 由玩家在設定頁輸入自己的 Gemini API key；請求從瀏覽器直接送往 Google API，不經遊戲伺服器。
- 指定模型 ID：`gemini-3.5-flash-lite`。
- Gemini 負責事件敘述、選項文字與回顧草稿；遊戲引擎負責驗證回應、套用數值規則與保存年表。
- 以結構化 JSON 回應降低格式錯誤；API key 不進存檔匯出，也不寫入原始碼或 Git。
- 金鑰儲存方式待討論：每次工作階段輸入，或由玩家選擇儲存在本機瀏覽器。

官方模型文件列出此模型支援結構化輸出，並指出 Gemini 3.5 Flash-Lite 不應傳入已棄用的 `temperature`、`top_p`、`top_k` 等參數。實作前仍會依官方 API 文件確認請求格式與可用能力。

- [Gemini 3.5 Flash-Lite API 變更](https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.6)

## 像素美術方向

- 溫暖、帶懷舊感的低解析度像素畫；畫面像一本會隨年歲改變的生活手帳。
- 角色立繪隨年齡成長，背景、季節與房間物件記錄人生階段。
- 主畫面可由「人物場景 + 年齡／狀態面板 + 人生時間軸 + 事件對話框」組成。
- 先建立少量一致的像素素材與色盤，再延伸不同年齡及事件場景。

## MVP 範圍建議

先完成一條可玩完的 80 年人生：角色建立、年份推進、選擇與突發事件、關係／狀態追蹤、本機存檔，以及結尾回顧。暫不加入多人、雲端帳號或需要伺服器保存的資料。

## 待討論

1. **回合節奏**：逐年都能做選擇，還是完整經過 80 年、只在重要人生節點停下來？
2. **人生背景**：以當代台灣為主，或採用不限定地區與年代的虛構背景？
3. **遊戲語氣**：偏溫暖治癒、寫實帶苦甜，或允許戲劇性與荒謬事件？
4. **BYOK 保存**：只在當次工作階段使用 key，或提供「記住此裝置」選項？

## 下一步

先決定回合節奏。它會影響每局需要多少次玩家輸入、Gemini 呼叫頻率，以及 80 年時間軸在畫面上的呈現方式。
