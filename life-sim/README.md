# 八十年｜人生模擬器

> 設計討論稿 v0.4｜工作名稱：八十年（Eighty Years）

## 一句話

用像素風格走過一個人的 80 年人生；時間按月份前進，人生階段、季節與偶發事件共同塑造一段獨一無二的生命故事，最後生成完整回顧。

## 已確認的設計方向

- **行事曆預設**：MVP 先採當代台灣行事曆，涵蓋學期、寒暑假與常見工作節奏；資料結構保留地區設定，之後可擴充其他地區。
- **事件密度**：採混合節奏。每月都能推進，但平常月份只給簡短生活摘要並可快轉；較少數的重要事件才暫停遊戲，讓玩家做選擇。
- **敘事參考**：日劇《重啟人生》（ブラッシュアップライフ）。參考其生活喜劇的日常觀察、自然閒聊與友情情感累積；遊戲聚焦玩家自己的 80 年人生。
- **事件機率**：事件種類與出現機率參考人生階段、月份／季節、學校或工作狀態、健康、關係與過往經歷；避免每月固定發生同一種事件。

## 敘事基調草案

- 生活細節放在前景：課堂、通勤、午餐、家庭對話、同事閒聊等普通時刻，讓人生大事件自然發生在日常之中。
- 幽默來自觀察、反應與對話節奏，不要求每個事件都安排笑點。
- 關係透過反覆相處和小事建立；早先的玩笑、承諾或習慣，可以在多年後以新的意義回到故事裡。
- 大多數月份輕鬆平實，少數月份帶來苦甜轉折；重要事件有份量，但不讓人生只由危機構成。
- 不同人生階段使用不同的生活語彙：校園裡的考試與朋友、職場裡的專案和午休、晚年裡的家庭與回憶。

**事件示例｜段考結束的午後**

最後一科考完，朋友拿著錯題本說要去圖書館檢討，另一位已經開始搜尋附近哪間冰店還開著。大家嘴上爭論到底要不要「立刻開始認真」，腳步卻慢慢往校門口移動。

- 跟朋友去吃冰，順便聽聽最近的八卦。
- 陪想檢討的朋友去圖書館，約好只待一小時。
- 先回家幫忙買菜，晚點再傳訊息問大家今天聊了什麼。

這類事件以熟悉的日常互動建立角色關係，玩家的選擇也可能在之後影響友情或家庭相處。

## 核心體驗

重點不是把人生玩成高分競賽，而是看見選擇如何累積：一次搬家、一段關係、一份工作或一場意外，可能在多年後才顯出影響。結局回顧呈現玩家如何生活，不替人生判定單一的成功標準。

## 初步遊戲循環

1. **建立角色**：設定姓名、出生年月、生活地區／行事曆、起點環境、個性傾向，以及此生最看重的事。
2. **逐月推進**：模擬 0–80 歲，每次推進一個月。平靜月份顯示簡短生活摘要；玩家可逐月前進，也可快轉到下個事件。
3. **機率性事件**：依人生階段、季節、學校或工作狀態、個人狀態和過往經歷調整事件種類與機率。
4. **做出選擇**：重要事件提供 2–3 個行動，也可輸入自訂行動。部分選擇會留下多年後才觸發的影響。
5. **保存與回顧**：每月狀態自動保存；到 80 歲後，生成重要時刻年表、人生狀態變化、關係故事、成就與遺憾，以及貼合玩家經歷的人生回顧。

## 人生階段與事件池

階段與年齡範圍先採可調整設定。MVP 的事件日曆以當代台灣為預設；地區與行事曆資料分離，避免未來新增地區時重寫遊戲規則。

| 階段 | 事件例子 |
| --- | --- |
| 幼年 | 家庭變化、興趣萌芽、搬家、健康與照顧 |
| 求學 | 開學、考試、社團、同儕關係、寒暑假活動與升學選擇 |
| 青年／初入職場 | 升學或求職、離家、實習、初次工作與建立新關係 |
| 職涯／家庭生活 | 專案、年度考核、升遷、轉職、同事活動、休假、伴侶與家庭事件 |
| 中年 | 職涯轉折、照顧責任、財務決定、關係維繫與新的興趣 |
| 晚年 | 退休安排、健康變化、家庭相聚、回望往事與生活重心轉換 |

事件權重會參考角色目前的身份與事件冷卻時間，避免連續幾個月都遇到同類事件。固定時節事件（如考試、假期、年度考核）由台灣行事曆設定提供；突發事件則再依狀態與過往選擇調整機率。

## 遊戲系統草案

- **可理解的狀態**：健康、情緒、經濟、工作／志業、關係，各以少量數值搭配文字描述。
- **重要人物**：家人、朋友、伴侶、同事等角色有自己的關係狀態與共同記憶。
- **事件與機率**：遊戲引擎依階段、月份、身份和狀態決定是否觸發事件；Gemini 撰寫事件內容及選項，不直接決定抽中機率。
- **延遲後果**：選擇先記錄成事件與狀態變化，後續事件可以引用它；避免 Gemini 任意改寫整份存檔。
- **人生回顧**：不以財富或職涯單一排名，依角色起點、玩家重視的事與實際經歷，整理「這一生如何成形」。

## 存檔與重來草案

- **自動存檔**：每次月份推進或事件結束後保存，包含年月、人生階段、行事曆設定、狀態、重要關係、未來待觸發的後果、事件紀錄與隨機種子。
- **繼續人生**：重新開啟遊戲時，可從最近一次自動存檔繼續。
- **重新開始**：開啟新人生時不覆蓋舊人生；完成或放棄的存檔可收進「人生相簿」。
- **重玩同一起點**：保留角色初始設定，可選擇沿用相同隨機種子重現事件序列，或使用新種子體驗不同人生。
- **資料位置**：MVP 先存在本機瀏覽器，提供多個存檔位；API key 與人生存檔分開處理，不納入匯出資料。

## Gemini BYOK 草案

- 由玩家在設定頁輸入自己的 Gemini API key；請求從瀏覽器直接送往 Google API，不經遊戲伺服器。
- 指定模型 ID：`gemini-3.5-flash-lite`。
- Gemini 負責事件敘述、選項文字與回顧草稿；遊戲引擎負責事件抽選、驗證回應、套用數值規則與保存年表。
- 以結構化 JSON 回應降低格式錯誤；API key 不進存檔匯出，也不寫入原始碼或 Git。
- 金鑰儲存方式待討論：每次工作階段輸入，或由玩家選擇儲存在本機瀏覽器。

官方模型文件列出此模型支援結構化輸出，並指出 Gemini 3.5 Flash-Lite 不應傳入已棄用的 `temperature`、`top_p`、`top_k` 等參數。實作前仍會依官方 API 文件確認請求格式與可用能力。

## 像素美術方向

- 溫暖、帶懷舊感的低解析度像素畫；畫面像一本會隨年歲改變的生活手帳。
- 角色立繪隨年齡成長，背景、季節與房間物件記錄人生階段。
- 主畫面可由「人物場景 + 年齡／狀態面板 + 月份時間軸 + 事件對話框」組成。
- 季節背景和小物件依月份切換，讓學期、假期與生活節奏在畫面上也能被看見。

## MVP 範圍建議

先完成一條可玩完的 80 年人生：角色建立、逐月推進、依人生階段抽選事件、選擇與延遲後果、關係／狀態追蹤、自動存檔、繼續／重開，以及結尾回顧。採混合事件密度、台灣行事曆預設與生活喜劇敘事。暫不加入多人、雲端帳號或需要伺服器保存的資料。
