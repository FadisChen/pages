🎙️ Gemini Live 即時語音對談測試

使用 Gemini Live API（WebSocket）打造的純前端即時語音對談頁面，BYOK（自備 API Key）。 專門用來測試兩件事：① 呼叫工具（tool）時 Gemini 能否邊「思考／說話」邊等候幾秒才回來的工具結果； ② 開啟「主動語音判斷」後，Gemini 能否依收到的聲音內容自行判斷需不需要回應。

⚙️ API 設定

Live 語音模型使用 AUDIO 輸出；文字除錯可開啟逐字稿並靜音喇叭。

進階設定（VAD 靈敏度／逐字稿）
🧠 啟用「主動語音判斷」(proactivity.proactiveAudio)
開啟後 Gemini 會自行判斷收到的聲音是不是在跟它說話；不相關的聲音（例如你在跟旁人講話、背景雜音）它會保持沉默、不回應。這個功能目前只在 v1alpha 版本可用，本頁已固定使用 v1alpha 端點。

🔧 本頁註冊的測試用工具

這兩個工具都是純前端模擬（setTimeout），不會真的打任何 API，只是用來製造「工具呼叫」與「刻意延遲幾秒才回應」的情境。

  1. get_current_time — 立即回傳目前時間，幾乎沒有延遲，作為對照組。
  2. slow_lookup(query) — 刻意延遲 4～7 秒（隨機）才回傳模擬查詢結果，用來測試 Gemini 是否會邊等待邊自然對話，而不是整段安靜卡住。

▶️ 連線與對話

💬 對話紀錄

🧪 建議測試腳本

  1. 測試①：非同步工具（NON_BLOCKING）——邊調用工具邊繼續對話。 連線後說（或打字）：「幫我查一下台北101的資料」。這句話會觸發 slow_lookup， 它刻意要等 4～7 秒才有結果，且已宣告為 behavior: "NON_BLOCKING"。 留意 Gemini 是不是會先說「好，我查一下」之類的話，並在等待這幾秒之間仍可以自然回應你的追問或閒聊， 而不是整段安靜卡住；結果出來後才用查到的內容接續對話。 右上角「Gemini 狀態」燈號會顯示「執行工具中」，之後可能轉成「背景思考／處理中」—— 這代表伺服器雖然送出 turnComplete:true，但 interactionStatus 仍是 IN_PROGRESS，代表 Gemini 還沒真正 idle，仍在背景處理。
    可以用上方「🧠 延伸思考版／⚡ 一般版」按鈕切換模型再重新連線比較： 延伸思考版通常會有更明顯的「先講一句、背景繼續處理、之後再接話」的行為； 一般版雖然一樣支援 NON_BLOCKING 工具，但沒有背景思考規劃的過程。
  2. 測試②：Gemini 能不能自己判斷要不要回應。 在「進階設定」打開「啟用主動語音判斷」後重新連線，然後：
    (a) 直接對它說「嗨 Gemini，現在幾點？」——應該正常回應（會觸發 get_current_time）。
    (b) 講一句明顯不是對它說的話，例如轉頭說「欸等一下要吃什麼」，或只是清喉嚨、背景雜音—— Gemini 應該保持安靜、不主動開口。可以對照關掉這個選項後的行為差異。

建議戴耳機測試，避免喇叭聲音被麥克風錄到造成回音／誤觸發。

API Key 與語音僅存在、僅使用於你目前的瀏覽器，直接以 WebSocket 呼叫 Gemini Live API，不會經過任何中介伺服器。
工具呼叫（get_current_time / slow_lookup）皆為前端模擬，不會送出任何額外的網路請求。
